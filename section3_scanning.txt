1) Theory behind scanning
    + focus on technology side 
    + looking for open ports
        80: http (web server)
        443: https
        21: ftp 
        22: ssh port 
        53: dns 
        25: smtp 

 2) tcp & udp 
    tcp: 3-way handshakes
        syn 
        syn-ack 
        ack 

    udp: throw all the error checking stuff out

3) Netdiscover: to figure how many host (machines) we have in our network 
    sudo arp -a --> display arp table on your computer, sometimes we have to ping successfully
another machines to get the result (so it showed on arp table), not so good tool

    sudo netdiscover --> find any available machines in local network, better solution

    netstat -nr --> to find default gateway or router

4) Performing First Nmap Scan 
    nmap --help --> get help of nmap 

    nmap 192.168.0.19 --> scan metasploitable machine, nmap by default scan 1000 ports 

    nmap 192.168.0.1/24 --> scan range of ip address 

5) Different Nmap Scan Types 
    a) tcp synscan 
        sudo nmap -sS 172.16.1.100 --> never open full tcp connection (just sendind syn), if the
    target sending synack back that means that port is listening or open, if target is sending
    RST or reset, that means port is closed, in case target does not send anything back after 
    several tries, port will be marked as filtered (could happen because of fireware)

        sudo nmap -sT 172.16.1.100 --> tcp connect scan, perform normal tcp three-way 
    handshakes connection, leave trace that you performed a nmap scan 

        sudo nmap -sU 172.16.1.100 --> scan udp ports

6) Discovering Target Operating System 
    sudo nmap -O 172.16.1.100 --> nmap scan with trying to get os version 
        (sometimes, we can get result like Oracle Virtualbox virtual NIC, meaning Nmap 
        figure this is a virtual machine such as honeypot)

    sudo nmap -O 172.16.1.213 --> trying to scan windows machine 

7) Detecting Version of Service Running on an Open Port 
    sudo nmap -sV 172.16.1.100 --> scanning and detecting version of service running 

    sudo nmap -sV --version-intensity 9 172.16.1.100 --> version scanning with intensity (0 - 9),
default level is 7 

    sudo nmap -A 172.16.1.100 --> for aggressive scanning, it enables version detection without
specifying -sV, it enable something called nmap script scanning 

8) Filtering Port Range and Output of Scan Results 
    -sn: ping scan, check which host discovery 

    sudo nmap -sn 172.16.1.1-255 --> check host from 1 to 255

    sudo nmap -p 80 172.16.1.100 --> scan specific port with '-p' option 

    sudo nmap -p 80,22,100 172.16.1.100 --> scan multiple ports
    sudo nmap -p 1-100 172.16.1.100 --> scan multiple ports

    sudo nmap -F 172.16.1.100 --> scan first 100 ports 

    sudo nmap -sS 172.16.1.100 >> output_of_scan.txt --> output scanning result 

    sudo nmap -oN output -sS 172.16.1.100 --> output to terminal and file at the same time 

9) What is Firewall/IDS 
    + network firewall: filter traffic between two or more networks
    + host-based firewall: filter traffic only going in or out from that specific machine 
    + IDS (intrusion detection system): software application that monitors network for any malicious
activity
    
10) Using decoys and packet fragmentation 
    sudo nmap -f 172.16.1.213 --> -f option is to use fragmented ip packets, split tcp header over
several packets to make it harder for packet filters or intrusion, default will split into 8 bytes or less, with 
(-f -f will split into 16 bytes)

    sudo nmap -D RND:5 172.16.1.213 -sS --> scanning using decoy (-D), RND:5 specify 5 ip addresses so when 
it scans, IDS will be have a hard time to know which ip is ours 

    sudo nmap -D 192.168.1.2,192.168.1.5,192.168.1.15,ME 192.168.1.213 --> using specified ip addresses 
to scan using decoy

11) Security Evasion Nmap Options 
    sudo nmap -S 8.8.8.8 -Pn -e eth0 -g 7777 
        Option	Function
            -S	Spoof source IP address
            -Pn	Skip host discovery
            -e	Specify network interface
            -g	Specify source port

    sudo nmap -sF 172.16.1.100 --> try to perform a FIN scan, if target response with RST: port is closed,
no-response means that port is open or filtered
        Note: the FIN flag (Finish) in TCP is used to indicate that a device has finished 
    sending data and wants to gracefully terminate a TCP connection
    
    Trying to avoid IDS: we can use -T 0 (paranoid) or 1 (sneaky)
